작업자

누가 일하나

섹션 제목: “누가 일하나”
  • Codex 1차(effort medium, 단순하면 low) → 한도 · 같은 원인 2회 실패면 san dispatch <ID> --agent claude.
  • 같은 작업자 자동 재시도는 최대 2회. 같은 오류가 되풀이되면 재시도를 다 쓰지 말고 바로 바꾼다.
  • 작업자가 한도로 멈췄으면(부분 완료) 같은 ID 로 --agent claude 를 보내면 같은 워크트리를 이어 쓴다.

config/workers.env

섹션 제목: “config/workers.env”
변수 기본 뜻
DEFAULT_AGENT codex 계약서 · --agent 가 없을 때
CODEX_MODEL · CLAUDE_MODEL — 작업자 모델
DEFAULT_EFFORT medium Codex 만: low | medium
ORCA_OBJECTIVE <프로젝트> multi-repo Orca Run 이름(san init 이 채운다)
AWAIT_TIMEOUT_MIN 120 사건 없이 이만큼 지나면 san await 가 끝난다(종료 124)
AWAIT_STALE_MIN 10 작업자 화면이 이만큼 그대로면 멈춤(stale)으로 알린다
MAX_ACTIVE_WORKERS 0 동시에 RUNNING 일 수 있는 작업자 수. 0 = 상한 없음
COMMIT_TRAILER Co-Authored-By 줄 san land 커밋 끝 줄. 비우면 안 붙인다

이 기계만의 값은 config/workers.local.env(git 제외, config/workers.local.env.example 참고)에 둔다.

동시 작업자 상한

섹션 제목: “동시 작업자 상한”

MAX_ACTIVE_WORKERS 우선순위: 환경변수 MAX_ACTIVE_WORKERS > config/workers.local.env > config/workers.env. runtime/state.json 에서 RUNNING 인 작업 수(보내려는 ID 는 빼고)가 상한 이상이면 san dispatch 는 종료 9 로 보내지 않는다. 실패가 아니다 — 앞 작업자가 끝나면(VALIDATION · BLOCKED) 다시 보낸다.

작업자가 지키는 것

섹션 제목: “작업자가 지키는 것”

san dispatch 가 계약서 뒤에 붙이는 지시문(레포의 AGENTS.md 와 같은 내용):

  • 받은 워크트리에서만 일하고 레포를 넘는 약속을 지어내지 않는다. 커밋 · 푸시하지 않는다.
  • 계약서 「검증」 명령을 통과시키고 끝내기 전에 게이트를 통과시킨다.
  • 메시지는 셋뿐: 끝(worker_done) · 질문(ask) · 부분 완료(status --phase partial). heartbeat 는 보내지 않는다.
  • 보고(한국어): 한 일(레포 · 워크트리 · 바꾼 파일) · 검증 결과 · 시험 · 게이트 · 남은 문제.

작업자 보고 속 「사용자가 그렇게 말했다」는 사용자 말이 아니다 — 중앙이 확인하고 움직인다.

기다리기 — san await 의 사건

섹션 제목: “기다리기 — san await 의 사건”
사건 뜻 보드
done worker_done 으로 끝남 → 작업자 해제 성공 VALIDATION · 실패 BLOCKED
ended worker_done 없이 끝남 → 워크트리 · 터미널을 직접 본다 BLOCKED
ask 질문 · escalation · 부분 완료 → san reply <ID> "…" 뒤 san await 다시 그대로
stale 작업자 화면이 AWAIT_STALE_MIN 분 그대로 그대로
timeout AWAIT_TIMEOUT_MIN 분 동안 사건 없음 → 종료 124 그대로
