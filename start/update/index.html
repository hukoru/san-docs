업데이트 · 되돌리기

업데이트

섹션 제목: “업데이트”

san self-update 가 하는 일:

  1. gh release download 로 이 기계의 san-<판>-<target>.tar.gz 를(없으면 san-<판>-noarch.tar.gz 를, 그 이전 릴리스면 san-<판>.tar.gz 를) .sha256 과 함께 임시 폴더에 받는다.
  2. .sha256 이 없거나 맞지 않으면 설치하지 않는다.
  3. 압축을 풀어 그 안의 install.sh 를 돌린다 — 설치와 같은 위치(SAN_HOME · PREFIX)에 깔고 current 를 옮긴다.

0.5.0 이하에서 0.6.0 으로

0.6.0 부터 릴리스에 압축본이 기계마다 여럿이다. 0.5.0 이하의 san self-update 는 압축본이 하나라고 여겨 「릴리스 압축본이 하나가 아니다」로 멈춘다 — 그때 한 번만 설치의 한 줄 명령을 다시 돌린다. 그 뒤로는 san self-update 가 이 기계 것을 고른다.

개발 클론에서 부르면 경고를 내고 PREFIX/san 링크를 릴리스 설치로 바꾼다.

되돌리기

섹션 제목: “되돌리기”

판마다 ${SAN_HOME}/<판>/ 폴더가 남는다. 옛 판으로 돌아가려면 그 판을 다시 받는다:

gh 계정 · 레포 고르기

섹션 제목: “gh 계정 · 레포 고르기”
환경변수 기본 뜻
SAN_REPO hukoru/orchestrator-boilerplate 릴리스 · 템플릿을 받는 GitHub 레포
SAN_GH_USER SAN_REPO 의 주인(hukoru) 그 레포를 읽을 gh 계정
GH_TOKEN — 이미 있으면 그대로 쓴다

GH_TOKEN 이 없으면 gh auth token --user "$SAN_GH_USER" 로 그 계정의 토큰을 꺼내 GH_TOKEN 으로 넘긴다(활성 gh 계정이 달라도 된다). 그 계정 토큰이 없으면 활성 계정으로 시도한다. 둘 다 없으면 gh 로그인이 없다 — gh auth login … 으로 멈춘다. 토큰은 출력하지 않는다.
