작업 보고서 · 타임라인

계약서 하나가 끝날 때마다 reports/<ID>.md 가 남는다. 누가 · 언제 · 무엇을 바꿨고 · 어떻게 검증했는지가 한 파일에 있고, san report serve 로 날짜별 타임라인 화면에서 본다.

요청부터 — 실시간 「진행 중」

섹션 제목: “요청부터 — 실시간 「진행 중」”

새 사용자 요청이 오면 맨 먼저 원문을 남긴다. 그 뒤 계약서를 쓰고 머리말에 **Request**: R<n> 을 넣는다.

모든 명령이 runtime/events.jsonl 에 사건을 한 줄씩 남긴다(쓰기에 실패해도 명령은 계속하고 경고만 낸다). 타임라인 맨 위 「진행 중」은 요청 카드(원문 인용 → 거기서 나온 계약서 줄)마다 단계 표시를 그린다:

사건 단계 남기는 곳
요청 · 닫힘 san request add · reopen / san request close
계약서 · 준비됨 새 계약서 파일 · 보드 줄(san board-sync · 서버 감시자), TODO → READY
보내기 · 대기 san dispatch — 워크트리 · 준비(SETUP) · 종료 9(작업자 상한)
작업 중 · 질문 · 검토 대기 · 막힘 san await — 작업자 메시지(진행 · 질문 · 부분 완료 · 끝, heartbeat 는 뺀다, 본문은 meta.body 에 4000자까지), 화면 멈춤
작업 중(답함) san reply — 질문에 보낸 답(meta.msg · meta.body)
검토 · 올림 · 완료 · 막힘 san land — 게이트 · 커밋 · 검증 · 푸시 · 정리, 실패는 막힘
보고서 · 윤문 보고서 쓰기 · 윤문 시작/끝/거부
스크린샷 (보내기 · 검토 대기 단계) san dispatch 의 작업 전 · san await 의 작업 후 화면 찍기 — 시작 · 장 수 · 막은 요청 · ⚠ 실패
  • 요청 카드는 ID · 제목 · 상태 수(진행 · 대기 · 막힘 · 실패 · 완료) · 경과 · 계약서 수와 원문 앞 세 줄만 보인다 — 긴 요청도 목록을 밀지 않는다. 단추: 「원문 전체 보기」 · 「작업 상세」 · 「실행 로그」 · 「결과 보고서」(올린 계약서가 있을 때).
  • Drawer(오른쪽 패널, 좁은 화면은 전체 화면): 탭 「원문(사용자 요청)」과 「작업자에게 전달한 지시(계약서)」를 나눠 보인다(계약서는 /api/contracts/<ID> — contracts/<ID>-*.md 만, 읽기 전용). Markdown ↔ 원문 전환 · 안에서 찾기(강조, Enter 로 다음) · 제목으로 만든 목차 · 복사 · 만든/닫은 시각 · 이어진 계약서. 토큰 모양 글자는 서버가 가린 그대로 보인다.
  • 작업 표: 계약서마다 한 줄 — 작업 · 레포 · 에이전트 · 모델 · Effort(runtime/state.json 에 dispatch 가 적은 값만, 없으면 「—」) · 상태 · 지금 단계(마지막 사건) · 걸린 시간(보낸 때 → 지금/올린 때) · 마지막 활동 · 재시도(작업자를 다시 띄운 횟수). 거르기 진행 · 대기(검토 대기 · 질문) · 완료 · 실패(BLOCKED) · 막힘(막힘 사건 · 의존 대기), 정렬 최근 활동 · 걸린 시간 · 에이전트 · 완료 시각. 줄을 누르면 단계 표시 · 작업자 질문과 답 · 화면 · 그 계약서의 사건이 펼쳐진다. 진행률(%)은 만들지 않는다. 아직 답하지 않은 질문은 줄을 펼치지 않아도 줄 아래에 본문이 펼쳐져 보이고, san reply 로 답하면 질문 아래에 답이 붙는다.
  • 사건 타임라인: 모든 사건을 시각순으로 — 시각 · ID · 종류 칩 · 한 줄 · 출처. 줄을 누르면 사건 원문(JSON). ID · 종류 · 시간 범위로 거르고, 맨 아래를 보고 있으면 따라 내려가며, 위로 올리면 멈추고 「새 사건 N개 ↓」가 뜬다. 막힘은 빨갛게, 질문은 호박색.
  • 경과 · 상대 시간은 1시간 아래 분, 48시간까지 시간, 그 뒤 날(「10일째」).
  • 계약서가 올라가고 보고서가 생기면 카드는 아래 날짜별 기록으로 내려간다.
  • 머리글: 진행 중 · 막힘 · 오늘 완료 수. 진행 중이 있으면 탭 제목이 (N) 작업 보고서. 「알림 켜기」를 누르면 질문 · 막힘 · 완료 때 데스크톱 알림.
  • 실시간은 SSE(/api/stream, 15초마다 ping)다. 끊기면 다시 잇고, 계속 안 되면 3초마다 묻기로 바꾼다.
  • 예전 작업(backfill)은 사건이 없어 기록에만 완료 카드로 보인다.

요청 닫기 — san request close

섹션 제목: “요청 닫기 — san request close”

시험으로 남긴 요청 · 그만둔 요청 · 다른 요청과 겹치는 요청은 닫는다. 닫지 않으면 계약서가 없는 요청은 「진행 중」에 계속 남는다.

  • 사건 「닫힘」(이유 · 메모)을 남기고 runtime/requests/R<n>.md 머리말에 closed_at · close_reason(· close_note)을 적는다. reopen 은 그 값을 지우고 사건 「요청」을 남긴다.
  • 이어진 계약서가 RUNNING · VALIDATION(runtime/state.json)이면 어느 것인지 보이고 거부한다. 그래도 닫으려면 --force. 강제로 닫아도 아직 도는(RUNNING · VALIDATION · BLOCKED) 계약서는 「진행 중」에 홀로 선 카드(「요청 R 은 닫힘」)로 남는다 — 올리거나 닫을 때까지.
  • 타임라인: 닫은 요청은 「진행 중」과 머리글 · 탭 제목의 수에서 빠지고, 날짜별 기록에 작은 카드(R<n> · 원문 · 「닫힘 · 이유」 · 이어진 계약서)로 남는다. 거르기 칩 「닫힘」. /api/state 의 요청마다 closed · close_reason · closed_at · close_note, 닫은 요청 목록은 live.closed.
  • san doctor 는 열린 지 7일이 넘었는데 이어진 계약서가 없는 요청에 ⚠ 를 낸다(고치기: san request close R<n> --reason …).

언제 생기나

섹션 제목: “언제 생기나”
때 누가 쓰나 상태
san land <ID> 가 푸시한 뒤(워크트리를 지우기 전) san land COMPLETED
작업자가 실패했거나 보고 없이 끝났을 때 san await BLOCKED + 막힌 이유
손으로 · 다시 만들 때 san report new <ID> 지금 runtime/state.json 의 상태

san report new <ID> 는 여러 번 돌려도 같다 — runtime/state.json · 계약서 · git · 작업자 보고로 다시 만들고, 내용이 같으면 파일을 건드리지 않는다.

보고서 모양

섹션 제목: “보고서 모양”

머리말은 키: <JSON 값> 줄이다(그대로 YAML 이기도 하다).

본문 절: 요약(계약서 「왜」 · 「할 것」 첫 줄) · 바뀐 것(파일 목록 · 커밋) · 검증(검증 명령 · 게이트) · 화면 (작업 전 · 후)(화면 스크린샷을 켠 프론트 레포만 — 화면 스크린샷) · 작업자 보고(작업자의 worker_done 본문 원문 — 제목은 한 단계 내린다) · 남은 위험(작업자 보고의 「남은 문제」). 토큰 모양 글자는 가리고, 환경 변수 값은 넣지 않는다.

윤문

섹션 제목: “윤문”
  • 결과는 reports/<ID>.polished.md(머리말 polished: true · polished_at · 원문 해시 source_hash). 원문 reports/<ID>.md 는 그대로 남는다.
  • 윤문 명령은 config/workers.env 의 REPORT_POLISH_CMD — 본문을 stdin 으로 받아 윤문한 본문만 stdout 으로 내는 명령이다. 비우면 claude CLI 를 claude -p "…" 로 부른다(humanize-korean 스킬로 가볍게 · 보수적으로, 내용 추가 · 삭제 없이).
  • 거부 규칙: 코드 블록 · 인라인 코드 · 파일 경로 · 숫자 · 계약서 ID · 제목 줄이 원문과 하나라도 다르거나 길이가 크게 바뀌면 버리고 원문을 둔다.
  • 윤문 명령이 없거나 실패하면 「윤문 대기」로 두고 종료 0 이다. san doctor 가 대기 수를 알려 준다.
  • REPORT_POLISH=auto(기본)면 san land 가 뒤에서 윤문을 돌린다(runtime/<ID>.polish.log). land 는 기다리지 않는다. 끄려면 REPORT_POLISH=off.
  • 원문을 다시 만들면(san report new) 해시가 달라져 다시 「윤문 대기」가 된다.

타임라인 화면

섹션 제목: “타임라인 화면”
  • 127.0.0.1 에만 묶는다. 읽기만 하고(GET 외에는 405), reports/ 밖의 파일은 내주지 않는다.
  • 화면은 3초마다 /api/version 을 보고 새 보고서가 생기면 다시 그린다 — land 가 끝나면 곧 나타난다.
  • 카드: 시각 · ID · 레포 색(REPOS 순서로 고정) · 상태(완료 초록 · 막힘 빨강 · 검토 중 파랑) · 제목 · 요약 두 줄 · 작업자 · 커밋 · 파일 +/- · 「윤문 전」 표시. 「자세히」로 본문을 펼친다. 「의존: B1」 을 누르면 그 카드로 간다.
  • 거르기: 레포 · 상태 칩, 글 검색(제목 · ID · 본문).
  • 본문 마크다운은 화면 안의 작은 렌더러가 그린다 — 먼저 HTML 을 모두 이스케이프하므로 본문의 <script> 는 글자로 보인다. 밖에서 받는 스크립트는 없다.

예전 작업 채우기

섹션 제목: “예전 작업 채우기”

보드에서 COMPLETED 인데 보고서가 없는 계약서마다, 계약서와 그 레포의 git 기록으로 보고서를 만든다(source: backfill). 커밋은 ① 제목이 계약서 Commit 줄과 같은 것 → ② 본문에 계약서: <ID> → ③ 제목에 ID 낱말 순서로 찾고, 날짜 · sha · 바뀐 파일을 쓴다. reports/ 의 옛 자료(그 ID 이름의 폴더 · 파일, ID 를 말하는 문서)는 「옛 자료」 절에 링크한다. 레포는 읽기만 하고, 이미 있는 보고서는 덮지 않는다.
